# Folder Tree Indentation

`FolderTreeRow` originally wrapped expandable nodes in a plain `DisclosureGroup(isExpanded:) { ... } label: { rowContent }`. On macOS, `DisclosureGroup`'s automatic style draws its own chevron ahead of the label and applies its own leading inset to disclosed content — neither amount is documented or controllable, and both would stack with the manual `depth * indentationPerDepth` padding on every recursive level. That compounding made per-depth step size unpredictable, and leaf rows (no chevron) never lined up with expandable rows (chevron + label) at the same depth.

Fix: stop using `DisclosureGroup` for the recursive tree. `FolderTreeRow` now renders its own chevron via a plain `Button` inside a fixed-width `disclosureColumnWidth` column, and leaf rows render an equal-width invisible `Color.clear` spacer in that same column, so icon/text always start at the same x-offset regardless of whether the row has children. Children are laid out in a plain `VStack` gated on `isExpanded`, not inside a `DisclosureGroup` content closure — so the `depth * indentationPerDepth` padding on `rowContent` is the *only* thing that grows indentation per level.

Lesson: don't nest `DisclosureGroup` recursively when you need a controlled, linear per-depth indent — its native macOS chevron/content-inset behavior isn't inspectable via static analysis and compounds with manual padding at every nesting level. Build the disclosure affordance manually (button + fixed-width reserved column) whenever exact alignment between chevron and non-chevron rows at the same depth is required.
